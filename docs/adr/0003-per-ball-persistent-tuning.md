# ADR-0003：采用按球持久化的玩法参数 Schema

## 状态

Accepted

## 日期

2026-08-16

## 背景

能力球的生命、伤害、冷却、范围、持续时间、概率、数量上限以及附属实体属性原本散落在模块、能力和实体脚本中。修改数值需要编辑代码，也无法从运行界面长期保留。若把这些值放进单局配置或场景倍率，同一个球会因对手或开局方式而得到不同的隐式默认值，场景也会重新拥有球的玩法细节。

项目需要允许直接把某个球调成任意强度，并让这组配置跟随该球参加所有组合。配置系统还必须维持核心不识别具体球 ID、球之间不互相引用的模块边界。

## 决策

每个 `BallModule` 在自己的 `scripts/balls/<id>/module.gd` 中声明参数 Schema。基础属性 `max_hp`、`speed`、`radius` 和 `cooldown` 自动注册；其他玩法数值通过 `tuning` 注册。每项包含稳定键、中文标签、默认值、最小值、最大值、步长、类型和排序信息。

所有会改变战斗结果、数量、时序、范围、概率或运动规则的值都属于参数 Schema。能力通过 `setting()`、`settingf()` 和 `settingi()` 读取已归一化的当前值，并在创建附属实体或状态时显式注入其参数。纯绘制坐标、颜色通道、音频采样率和数值误差常量不进入玩法配置。

本体生命值的默认值统一为 100；有独立生命的附属物默认生命值为 10。场景可以选择参战球和球内 profile，但不为了延长对局或补偿强弱而覆盖伤害、回复、生命和冷却。

`BallRegistry` 保存一份按球 ID 分组的运行时覆盖字典。注册模块时，它只把某个 ID 下的字典交给对应模块，不解释参数键，也不把一个球的值合并给另一个球。

`BallSettingsStore` 使用版本化 JSON 文档保存完整的 `ball_id -> settings` 映射，默认路径为 `user://ability_ball_settings.json`。主入口在应用启动时加载一次，经注册表归一化后作为当前运行时配置。开始对局、重开、随机种子和切换对手只创建新的战斗实例，不重置或重新解释球参数。所有组合共享的时限与竞技场尺寸属于独立的全局设置，不进入该映射。

`BallSettingsDialog` 从注册表读取 Schema 动态生成输入项。用户提交后，应用重新配置注册表、保存完整的归一化映射并重开当前对局。“恢复此球默认”只修改弹窗中当前球的工作副本，提交后才持久化。

## 理由

- 参数定义与玩法实现同属一个球目录，修改球 A 不要求修改球 B、存储层或弹窗。
- 配置以球为生命周期，而不是以对局为生命周期；同一个球跨对手、种子和应用启动保持一致。
- 通用层只理解 Schema 元数据，新增球和新增参数无需增加具体分支。
- 范围归一化集中在 `BallModule`，UI、文件和测试得到相同的有效值。
- 场景不承担平衡责任，极端参数也能按用户设定原样进入战斗。

## 考虑过的方案

### 每局保存一份双方配置

可以复现某次对局，但同一个球在不同组合中会产生多套默认值，切换对手后容易丢失调参结果，因此不采用。

### 使用一张全局通用参数表

实现简单，但不同球的伤害、召唤物和技能参数没有相同语义，也会迫使公共核心认识具体球种，因此不采用。

### 在场景中维护强度倍率

可以快速拉长展示时长，但结果不再只由球自身配置决定，并重新引入组合级平衡耦合，因此不采用。

### 每个球使用独立配置文件和独立弹窗

文件所有权直观，但会重复持久化、版本和 UI 代码。采用一个版本化文档和一个 Schema 驱动弹窗仍能保持按球隔离。

## 后果

### 正面

- 所有球都能从界面长期调参，不需要改代码或为每种球编写专用表单。
- 分身、浮游炮和其他附属物与本体共享所属球的配置生命周期。
- 新对局自动使用当前球配置，视频工具通过主入口运行时也读取相同值。
- 测试可以覆盖参数生效和隔离，而不锁定胜者、时长或胜率。

### 负面

- 每个新增玩法数值都必须维护 Schema 元数据和合理的输入范围。
- 参数可以被调到极端值，导致对局很快结束、画面拥挤或性能下降；这是允许的配置结果，由硬时限和数量上限范围保护运行边界。
- 修改稳定键或文件格式需要显式的版本迁移决策。

### 中性

- 测试默认从模块默认值开始，不读取开发者机器上的用户文件，避免个人调参改变持续集成结果。
- “恢复默认”是逐球操作，不存在恢复整局双方默认的隐式行为。

## 安全与隐私

配置文件只包含公开玩法数值和球 ID，不保存账号、凭据或设备标识。文件只从 Godot 的 `user://` 目录读取，不接受脚本路径、资源路径或可执行内容。载入值必须经过所属模块的类型和范围归一化，损坏或不支持版本的文档不会参与注册。

## 失败处理

- 文件不存在：所有球使用自己的 Schema 默认值。
- JSON 损坏、根类型错误或版本不支持：发出警告并忽略整份文件。
- 未知球 ID：注册表不会创建模块，也不会把其值应用给其他球；下一次保存只保留当前已注册球的归一化快照。
- 参数缺失或类型无效：该参数使用所属球默认值。
- 参数越界：按 Schema 截断并按步长归一化。
- 保存失败：当前进程仍可使用已应用值，界面明确提示未能跨启动保存。
